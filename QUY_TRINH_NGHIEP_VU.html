1. QUY TRÌNH NGHIỆP VỤ CHUNG

1.1. Tổng quan hệ thống

Hệ thống bán tranh nghệ thuật trực tuyến là nền tảng kết nối giữa họa sĩ và người mua, cho phép:

  • Họa sĩ đăng tải và bán tác phẩm nghệ thuật
  • Người dùng tìm kiếm, xem và mua tranh trực tuyến
  • Admin quản lý toàn bộ hệ thống, duyệt tác phẩm và đơn hàng

1.2. Các vai trò trong hệ thống

Vai trò Mô tả Quyền hạn chính
Admin Quản trị viên hệ thống - Quản lý toàn bộ hệ thống
- Duyệt tác phẩm, bài viết
- Quản lý đơn hàng, người dùng, họa sĩ
- Xem báo cáo thống kê
Họa sĩ (Artist) Người tạo và bán tác phẩm - Đăng tải tác phẩm
- Quản lý tác phẩm cá nhân
- Viết bài giới thiệu
- Xem doanh thu
Người dùng (Customer) Khách hàng mua tranh - Xem và tìm kiếm tác phẩm
- Thêm vào giỏ hàng
- Đặt mua và thanh toán
- Quản lý đơn hàng cá nhân
Khách (Guest) Người truy cập chưa đăng nhập - Xem tác phẩm công khai
- Xem thông tin họa sĩ
- Đăng ký tài khoản

1.3. Luồng hoạt động tổng quát

LUỒNG HOẠT ĐỘNG CHÍNH

Họa sĩ đăng tác phẩm → Admin duyệt → Tác phẩm hiển thị công khai → Người dùng xem và mua → Xử lý đơn hàng → Giao hàng → Hoàn thành

2. QUY TRÌNH NGHIỆP VỤ THEO VAI TRÒ

2.1. QUY TRÌNH NGHIỆP VỤ ADMIN

2.1.1. Đăng nhập hệ thống

Mục đích: Xác thực và truy cập vào trang quản trị

Điều kiện tiên quyết: Có tài khoản Admin

Các bước thực hiện:

Bước 1: Admin truy cập trang đăng nhập (/login)
Bước 2: Nhập tên đăng nhập và mật khẩu
Bước 3: Hệ thống kiểm tra thông tin:
  • Kiểm tra tài khoản có tồn tại không
  • Xác thực mật khẩu (BCrypt)
  • Kiểm tra vai trò = Admin (VaiTro = 0)
  • Kiểm tra trạng thái tài khoản (TrangThai = 1)
Bước 4: Nếu hợp lệ:
  • Tạo JWT token với claims: MaTaiKhoan, TenDangNhap, Role=Admin
  • Token có thời hạn 7 ngày
  • Trả về token cho client
Bước 5: Client lưu token vào localStorage
Bước 6: Chuyển hướng đến trang Admin Dashboard (/admin)

Kết quả: Admin đăng nhập thành công và truy cập được trang quản trị

Lưu ý: Nếu đăng nhập thất bại, hệ thống hiển thị thông báo lỗi cụ thể: "Tài khoản không tồn tại", "Mật khẩu không đúng", hoặc "Tài khoản đã bị khóa".

2.1.2. Quản lý tác phẩm

2.1.2.1. Xem danh sách tác phẩm chờ duyệt

Mục đích: Xem tất cả tác phẩm họa sĩ gửi lên chờ duyệt

Điều kiện tiên quyết: Đã đăng nhập với vai trò Admin

Các bước thực hiện:

Bước 1: Admin vào menu "Quản lý tác phẩm"
Bước 2: Hệ thống gọi API: GET /api/admin/tac-pham/get-all?trangThai=0
Bước 3: Backend truy vấn database: 
SELECT tp.*, hs.TenHoaSi, dm.TenDanhMuc
FROM TacPham tp
INNER JOIN HoaSi hs ON tp.MaHoaSi = hs.MaHoaSi
INNER JOIN DanhMuc dm ON tp.MaDanhMuc = dm.MaDanhMuc
WHERE tp.TrangThai = 0  -- Chờ duyệt
ORDER BY tp.NgayTao DESC
Bước 4: Hiển thị danh sách tác phẩm với thông tin:
  • Hình ảnh tác phẩm
  • Tên tác phẩm
  • Tên họa sĩ
  • Danh mục
  • Giá bán
  • Ngày tạo
  • Các nút: Duyệt, Từ chối, Xem chi tiết

Kết quả: Admin thấy danh sách tác phẩm chờ duyệt

2.1.2.2. Duyệt tác phẩm

Mục đích: Phê duyệt tác phẩm để hiển thị công khai

Điều kiện tiên quyết: Tác phẩm đang ở trạng thái "Chờ duyệt" (TrangThai = 0)

Các bước thực hiện:

Bước 1: Admin nhấn nút "Duyệt" trên tác phẩm
Bước 2: Hệ thống gọi API: PUT /api/admin/tac-pham/{id}/update/duyet 
Body: {
  "trangThai": 1,  // 1 = Đang bán
  "lyDo": null
}
Bước 3: Backend thực hiện:
  • Kiểm tra tác phẩm có tồn tại không
  • Kiểm tra trạng thái hiện tại = 0 (Chờ duyệt)
  • Cập nhật TrangThai = 1 (Đang bán)
  • Cập nhật NgayCapNhat = GETDATE()
UPDATE TacPham
SET TrangThai = 1,
    NgayCapNhat = GETDATE()
WHERE MaTacPham = @MaTacPham
  AND TrangThai = 0
Bước 4: Hệ thống trả về thông báo "Duyệt tác phẩm thành công"
Bước 5: Tác phẩm được hiển thị công khai trên trang chủ

Kết quả: Tác phẩm được duyệt và hiển thị công khai cho người dùng

2.1.2.3. Từ chối tác phẩm

Mục đích: Từ chối tác phẩm không đạt yêu cầu

Điều kiện tiên quyết: Tác phẩm đang ở trạng thái "Chờ duyệt" (TrangThai = 0)

Các bước thực hiện:

Bước 1: Admin nhấn nút "Từ chối" trên tác phẩm
Bước 2: Hiển thị modal nhập lý do từ chối
Bước 3: Admin nhập lý do (bắt buộc), ví dụ:
  • "Hình ảnh không rõ nét"
  • "Nội dung không phù hợp"
  • "Giá không hợp lý"
  • "Thiếu thông tin mô tả"
Bước 4: Hệ thống gọi API: PUT /api/admin/tac-pham/{id}/update/duyet 
Body: {
  "trangThai": 3,  // 3 = Từ chối
  "lyDo": "Hình ảnh không rõ nét"
}
Bước 5: Backend cập nhật: 
UPDATE TacPham
SET TrangThai = 3,
    LyDo = @LyDo,
    NgayCapNhat = GETDATE()
WHERE MaTacPham = @MaTacPham
Bước 6: Họa sĩ nhận thông báo tác phẩm bị từ chối kèm lý do

Kết quả: Tác phẩm bị từ chối, họa sĩ có thể chỉnh sửa và gửi lại

Quan trọng: Lý do từ chối phải rõ ràng, cụ thể để họa sĩ biết cách chỉnh sửa.

2.1.3. Quản lý đơn hàng

2.1.3.1. Xem danh sách đơn hàng

Mục đích: Xem tất cả đơn hàng trong hệ thống

Các bước thực hiện:

Bước 1: Admin vào menu "Quản lý đơn hàng"
Bước 2: Hệ thống gọi API: GET /api/admin/don-hang/get-all
Bước 3: Backend truy vấn: 
SELECT 
    hd.MaHoaDon,
    hd.MaNguoiDung,
    nd.Ten AS TenNguoiDung,
    tp.TenTacPham,
    hs.TenHoaSi,
    hd.SoLuong,
    hd.DonGia,
    hd.ThanhTien,
    hd.NgayDat,
    hd.TrangThai,
    hd.DiaChiGiao
FROM HoaDonBan hd
INNER JOIN NguoiDung nd ON hd.MaNguoiDung = nd.MaNguoiDung
INNER JOIN TacPham tp ON hd.MaTacPham = tp.MaTacPham
INNER JOIN HoaSi hs ON tp.MaHoaSi = hs.MaHoaSi
ORDER BY hd.NgayDat DESC
Bước 4: Hiển thị danh sách với các trạng thái:
Trạng thái Giá trị Màu hiển thị
Chờ xác nhận 0 Vàng
Đã xác nhận 1 Xanh dương
Đang giao 2 Cam
Đã giao 3 Xanh lá
Hoàn thành 4 Xanh đậm
Đã hủy 5 Đỏ

Kết quả: Admin thấy toàn bộ đơn hàng và trạng thái

2.1.3.2. Cập nhật trạng thái đơn hàng

Mục đích: Thay đổi trạng thái đơn hàng theo quy trình

Quy trình trạng thái:

Chờ xác nhận (0) → Đã xác nhận (1) → Đang giao (2) → Đã giao (3) → Hoàn thành (4)

Có thể hủy (5) ở bất kỳ bước nào trước "Đã giao"

Các bước thực hiện:

Bước 1: Admin chọn đơn hàng cần cập nhật
Bước 2: Chọn trạng thái mới từ dropdown
Bước 3: Hệ thống kiểm tra logic chuyển trạng thái:
  • Không thể chuyển từ "Hoàn thành" sang trạng thái khác
  • Không thể chuyển từ "Đã hủy" sang trạng thái khác
  • Không thể chuyển ngược (ví dụ: từ "Đang giao" về "Chờ xác nhận")
Bước 4: Gọi API: PUT /api/admin/don-hang/{id}/update/trang-thai 
Body: {
  "trangThai": 2  // Đang giao
}
Bước 5: Backend cập nhật: 
UPDATE HoaDonBan
SET TrangThai = @TrangThai,
    NgayCapNhat = GETDATE()
WHERE MaHoaDon = @MaHoaDon
Bước 6: Gửi email thông báo cho khách hàng về trạng thái mới

Kết quả: Đơn hàng được cập nhật trạng thái, khách hàng nhận thông báo

2.2. QUY TRÌNH NGHIỆP VỤ HỌA SĨ

2.2.1. Đăng ký tài khoản họa sĩ

Mục đích: Tạo tài khoản để đăng tải và bán tác phẩm

Các bước thực hiện:

Bước 1: Truy cập trang đăng ký (/register)
Bước 2: Chọn "Đăng ký với tư cách Họa sĩ"
Bước 3: Điền form đăng ký:
  • Tên đăng nhập: Duy nhất, 6-50 ký tự
  • Mật khẩu: Tối thiểu 6 ký tự
  • Xác nhận mật khẩu: Phải trùng với mật khẩu
  • Tên họa sĩ: Tên hiển thị công khai
  • Email: Để liên hệ và nhận thông báo
  • Số điện thoại: Liên hệ
  • Địa chỉ: Địa chỉ làm việc
  • Tiểu sử: Giới thiệu về bản thân (tùy chọn)
  • Chuyên môn: Lĩnh vực nghệ thuật (tùy chọn)
Bước 4: Hệ thống validate:
  • Kiểm tra tên đăng nhập chưa tồn tại
  • Kiểm tra email hợp lệ
  • Kiểm tra mật khẩu và xác nhận mật khẩu trùng nhau
Bước 5: Gọi API: POST /api/auth/dang-ky 
Body: {
  "tenDangNhap": "hoasi_nguyen",
  "matKhau": "123456",
  "vaiTro": 2,  // 2 = Họa sĩ
  "tenHoaSi": "Nguyễn Văn A",
  "email": "nguyenvana@gmail.com",
  "dienThoai": "0901234567",
  "diaChi": "Hà Nội",
  "tieuSu": "Họa sĩ với 10 năm kinh nghiệm",
  "chuyenMon": "Tranh sơn dầu"
}
Bước 6: Backend thực hiện:
  • Hash mật khẩu bằng BCrypt (work factor = 11)
  • Tạo record trong bảng TaiKhoan (VaiTro = 2)
  • Tạo record trong bảng HoaSi với MaTaiKhoan vừa tạo
  • Trạng thái mặc định: TrangThai = 1 (Hoạt động)
BEGIN TRANSACTION;

-- Tạo tài khoản
INSERT INTO TaiKhoan (TenDangNhap, MatKhau, VaiTro, NgayTao, TrangThai)
VALUES (@TenDangNhap, @HashedPassword, 2, GETDATE(), 1);

DECLARE @MaTaiKhoan INT = SCOPE_IDENTITY();

-- Tạo hồ sơ họa sĩ
INSERT INTO HoaSi (MaTaiKhoan, TenHoaSi, Email, DienThoai, DiaChi, TieuSu, ChuyenMon, NgayTao, TrangThai)
VALUES (@MaTaiKhoan, @TenHoaSi, @Email, @DienThoai, @DiaChi, @TieuSu, @ChuyenMon, GETDATE(), 1);

COMMIT TRANSACTION;
Bước 7: Gửi email xác nhận đăng ký thành công
Bước 8: Chuyển hướng đến trang đăng nhập

Kết quả: Tài khoản họa sĩ được tạo thành công

2.2.2. Đăng tải tác phẩm mới

Mục đích: Đăng tác phẩm lên hệ thống để bán

Điều kiện tiên quyết: Đã đăng nhập với vai trò Họa sĩ

Các bước thực hiện:

Bước 1: Họa sĩ vào trang "Tác phẩm của tôi" (/artist/artworks)
Bước 2: Nhấn nút "Thêm tác phẩm mới"
Bước 3: Điền form tạo tác phẩm:
Trường Bắt buộc Mô tả
Tên tác phẩm Có Tối đa 200 ký tự
Danh mục Có Chọn từ danh sách có sẵn
Giá bán Có Từ 1,000 đến 1,000,000,000 VNĐ
Số lượng Có Từ 1 đến 100
Hình ảnh Có JPG, PNG, tối đa 5MB
Mô tả Không Mô tả chi tiết tác phẩm
Kích thước Không Ví dụ: 60x80cm
Chất liệu Không Ví dụ: Sơn dầu trên canvas
Chất liệu khung Không Ví dụ: Khung gỗ sồi
Bước 4: Upload hình ảnh:
  • Chọn file từ máy tính
  • Hệ thống kiểm tra định dạng và kích thước
  • Upload lên server hoặc cloud storage
  • Lưu URL hình ảnh
Bước 5: Nhấn "Tạo tác phẩm"
Bước 6: Hệ thống validate dữ liệu:
  • Tên tác phẩm không được để trống
  • Giá phải > 0
  • Số lượng phải >= 1
  • Phải có hình ảnh
Bước 7: Gọi API: POST /api/hoa-si/tac-pham/create 
Headers: {
  "Authorization": "Bearer {token}"
}
Body: {
  "tenTacPham": "Hoàng Hôn Trên Biển",
  "maDanhMuc": 1,
  "gia": 5000000,
  "soLuong": 1,
  "hinhAnh": "https://storage.com/images/artwork123.jpg",
  "moTa": "Bức tranh mô tả cảnh hoàng hôn tuyệt đẹp...",
  "kichThuoc": "60x80cm",
  "chatLieu": "Sơn dầu trên canvas",
  "chatLieuKhung": "Khung gỗ sồi"
}
Bước 8: Backend xử lý:
  • Lấy MaHoaSi từ JWT token
  • Validate business rules
  • Insert vào database với TrangThai = 0 (Chờ duyệt)
INSERT INTO TacPham (
    MaHoaSi, MaDanhMuc, TenTacPham, MoTa, Gia, HinhAnh,
    SoLuong, TrangThai, NgayTao, LuotXem,
    KichThuoc, ChatLieu, ChatLieuKhung
)
VALUES (
    @MaHoaSi, @MaDanhMuc, @TenTacPham, @MoTa, @Gia, @HinhAnh,
    @SoLuong, 0, GETDATE(), 0,
    @KichThuoc, @ChatLieu, @ChatLieuKhung
);

SELECT SCOPE_IDENTITY() AS MaTacPham;
Bước 9: Hiển thị thông báo "Tạo tác phẩm thành công. Đang chờ admin duyệt."
Bước 10: Tác phẩm xuất hiện trong danh sách với badge "Chờ duyệt" (màu vàng)

Kết quả: Tác phẩm được tạo và chờ admin duyệt

Lưu ý: Tác phẩm chỉ hiển thị công khai sau khi admin duyệt (TrangThai = 1).

2.2.3. Chỉnh sửa tác phẩm

Mục đích: Cập nhật thông tin tác phẩm

Điều kiện tiên quyết: Tác phẩm thuộc về họa sĩ hiện tại

Các bước thực hiện:

Bước 1: Họa sĩ vào trang "Tác phẩm của tôi"
Bước 2: Nhấn nút "Sửa" (icon bút chì) trên tác phẩm
Bước 3: Hệ thống load thông tin hiện tại vào form
Bước 4: Họa sĩ chỉnh sửa thông tin cần thiết
Bước 5: Nhấn "Cập nhật"
Bước 6: Hệ thống xử lý theo trạng thái hiện tại:
Trạng thái hiện tại Hành động
Chờ duyệt (0) Cập nhật trực tiếp, vẫn giữ TrangThai = 0
Đang bán (1) Tạo bản chỉnh sửa trong bảng TacPhamChinhSua, chờ admin duyệt
Ẩn (2) Cập nhật trực tiếp, vẫn giữ TrangThai = 2
Từ chối (3) Cập nhật và đổi TrangThai = 0 (Chờ duyệt lại)
Bước 7: Nếu tác phẩm đang bán (TrangThai = 1):
  • Tạo record trong bảng TacPhamChinhSua
  • Lưu nội dung chỉnh sửa với TrangThai = 0 (Chờ duyệt)
  • Tác phẩm gốc vẫn hiển thị công khai
  • Admin sẽ duyệt bản chỉnh sửa
INSERT INTO TacPhamChinhSua (
    MaTacPham, TenTacPham, MaDanhMuc, Gia, SoLuong,
    MoTa, HinhAnh, KichThuoc, ChatLieu, ChatLieuKhung,
    NgayChinhSua, TrangThai
)
VALUES (
    @MaTacPham, @TenTacPham, @MaDanhMuc, @Gia, @SoLuong,
    @MoTa, @HinhAnh, @KichThuoc, @ChatLieu, @ChatLieuKhung,
    GETDATE(), 0
);
Bước 8: Nếu tác phẩm bị từ chối (TrangThai = 3):
  • Cập nhật trực tiếp vào bảng TacPham
  • Đổi TrangThai = 0 (Chờ duyệt lại)
  • Xóa LyDo từ chối
UPDATE TacPham
SET TenTacPham = @TenTacPham,
    MaDanhMuc = @MaDanhMuc,
    Gia = @Gia,
    SoLuong = @SoLuong,
    MoTa = @MoTa,
    HinhAnh = @HinhAnh,
    KichThuoc = @KichThuoc,
    ChatLieu = @ChatLieu,
    ChatLieuKhung = @ChatLieuKhung,
    TrangThai = 0,  -- Chờ duyệt lại
    LyDo = NULL,
    NgayCapNhat = GETDATE()
WHERE MaTacPham = @MaTacPham
  AND MaHoaSi = @MaHoaSi;

Kết quả: Tác phẩm được cập nhật theo quy trình phù hợp

2.2.4. Xóa tác phẩm (Soft Delete)

Mục đích: Xóa tác phẩm khỏi danh sách hiển thị

Điều kiện tiên quyết: Tác phẩm không có trong đơn hàng đang xử lý

Các bước thực hiện:

Bước 1: Họa sĩ nhấn nút "Xóa" (icon thùng rác) trên tác phẩm
Bước 2: Hiển thị dialog xác nhận: "Bạn có chắc muốn xóa tác phẩm này?"
Bước 3: Họa sĩ xác nhận xóa
Bước 4: Gọi API: DELETE /api/hoa-si/tac-pham/{id}/delete
Bước 5: Backend kiểm tra:
  • Tác phẩm có thuộc về họa sĩ không
  • Tác phẩm có trong đơn hàng đang xử lý không (TrangThai 0,1,2)
-- Kiểm tra đơn hàng
IF EXISTS (
    SELECT 1 FROM HoaDonBan
    WHERE MaTacPham = @MaTacPham
      AND TrangThai IN (0, 1, 2)  -- Chờ xác nhận, Đã xác nhận, Đang giao
)
BEGIN
    THROW 50001, N'Không thể xóa tác phẩm đang có trong đơn hàng', 1;
END
Bước 6: Nếu hợp lệ, thực hiện soft delete: 
UPDATE TacPham
SET TrangThai = 99,  -- 99 = Đã xóa
    NgayCapNhat = GETDATE()
WHERE MaTacPham = @MaTacPham
  AND MaHoaSi = @MaHoaSi;
Bước 7: Tác phẩm biến mất khỏi danh sách "Tác phẩm của tôi"
Bước 8: Tác phẩm xuất hiện trong "Tác phẩm đã xóa" (có thể khôi phục)

Kết quả: Tác phẩm được đánh dấu đã xóa, có thể khôi phục sau

Quan trọng: Hệ thống sử dụng soft delete (TrangThai = 99) thay vì xóa vật lý để:
  • Bảo vệ dữ liệu khỏi xóa nhầm
  • Cho phép khôi phục khi cần
  • Giữ lại lịch sử đơn hàng

2.2.5. Khôi phục tác phẩm đã xóa

Mục đích: Khôi phục tác phẩm đã xóa nhầm

Điều kiện tiên quyết: Tác phẩm đang ở trạng thái "Đã xóa" (TrangThai = 99)

Các bước thực hiện:

Bước 1: Họa sĩ vào trang "Tác phẩm đã xóa" (/artist/artworks/deleted)
Bước 2: Hệ thống hiển thị danh sách tác phẩm có TrangThai = 99
Bước 3: Họa sĩ nhấn nút "Khôi phục" (màu xanh lá)
Bước 4: Hiển thị dialog xác nhận
Bước 5: Gọi API: PUT /api/hoa-si/tac-pham/{id}/khoi-phuc
Bước 6: Backend khôi phục: 
UPDATE TacPham
SET TrangThai = 0,  -- 0 = Chờ duyệt
    NgayCapNhat = GETDATE()
WHERE MaTacPham = @MaTacPham
  AND MaHoaSi = @MaHoaSi
  AND TrangThai = 99;
Bước 7: Tác phẩm quay lại danh sách "Tác phẩm của tôi" với trạng thái "Chờ duyệt"
Bước 8: Admin cần duyệt lại trước khi tác phẩm hiển thị công khai

Kết quả: Tác phẩm được khôi phục và chờ duyệt lại

2.3. QUY TRÌNH NGHIỆP VỤ NGƯỜI DÙNG

2.3.1. Đăng ký tài khoản người dùng

Mục đích: Tạo tài khoản để mua tranh

Các bước thực hiện:

Bước 1: Truy cập trang đăng ký (/register)
Bước 2: Chọn "Đăng ký với tư cách Người dùng"
Bước 3: Điền form đăng ký:
  • Tên đăng nhập (bắt buộc)
  • Mật khẩu (bắt buộc)
  • Xác nhận mật khẩu (bắt buộc)
  • Họ tên (bắt buộc)
  • Email (bắt buộc)
  • Số điện thoại (tùy chọn)
  • Địa chỉ (tùy chọn)
Bước 4: Gọi API: POST /api/auth/dang-ky 
Body: {
  "tenDangNhap": "user123",
  "matKhau": "123456",
  "vaiTro": 1,  // 1 = Người dùng
  "ten": "Nguyễn Văn B",
  "email": "user@gmail.com",
  "dienThoai": "0902345678",
  "diaChi": "TP.HCM"
}
Bước 5: Backend tạo tài khoản: 
BEGIN TRANSACTION;

-- Tạo tài khoản
INSERT INTO TaiKhoan (TenDangNhap, MatKhau, VaiTro, NgayTao, TrangThai)
VALUES (@TenDangNhap, @HashedPassword, 1, GETDATE(), 1);

DECLARE @MaTaiKhoan INT = SCOPE_IDENTITY();

-- Tạo hồ sơ người dùng
INSERT INTO NguoiDung (MaTaiKhoan, Ten, Email, DienThoai, DiaChi, NgayTao)
VALUES (@MaTaiKhoan, @Ten, @Email, @DienThoai, @DiaChi, GETDATE());

-- Tạo giỏ hàng
DECLARE @MaNguoiDung INT = SCOPE_IDENTITY();
INSERT INTO GioHang (MaNguoiDung, NgayTao)
VALUES (@MaNguoiDung, GETDATE());

COMMIT TRANSACTION;

Kết quả: Tài khoản người dùng được tạo kèm giỏ hàng
